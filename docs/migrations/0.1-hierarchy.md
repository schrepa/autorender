# Migrating to hierarchy and prefab authoring

Scene versions 1 and 2 remain loadable unchanged. To use parents, transform-only
nodes or prefab definitions, set `version` to 3, increment the source revision,
and validate/save through the shared authoring commands. The generated current
schema is `docs/schema/scene-v3.schema.json`; v1/v2 artifacts remain historical.

Numerical admission is tighter for all versions: composed matrices must be finite
and invertible, with finite inverse/cofactor data. The normal matrix is normalized
by its largest absolute coefficient and its inverse infinity norm must be at most
10,000. Previously accepted extreme anisotropy or near-singular shear can now be
rejected; reduce that scale ratio or shear. Large uniform scales do not alone
violate this conditioning bound. Lighting rescales normal calculations to avoid
overflow/underflow during normalization.

`SceneObject.mesh` and `.material` are now `Option<String>` in Rust. Wrap old
literal references in `Some`; JSON string references remain unchanged. Both must
be present or both absent. Rust literals also supply `parent: None`,
`prefab: None` and `SceneDocument.prefabs: Vec::new()` for legacy flat scenes.
Use `expanded_entities()` when a tool needs a validated flat view, and
`SceneInstance::entities()` plus `SceneEntity` metadata for runtime setup.

`Transform` now means local transform when parented. Read `GlobalTransform` for
world positions/matrices after a documented propagation boundary. Do not flatten
the matrix into rotation/scale: inherited nonuniform scale can produce shear.
Parenting preserves local values, so preserving a previous world pose requires
an explicit application decision. Use checked `set_parent`/`set_parents`; removing
a parent does not despawn its children or transfer ownership.

To reuse an object, move its records into one `ScenePrefab` with local IDs and
create `SceneObject` placement roots with `prefab`. Keep shared assets at the
document level. Expanded child IDs are `placement.local`; update external parent
references accordingly and let validation reject collisions or excessive length.
Nested prefabs and per-instance child overrides are not supported.

The importer now emits version 3 with provenance `static-glb-2`. Flat imports
keep their geometry behavior and preserve authored parents on replacement.
`--as-prefab` emits a definition without automatically placing it. Replacing an
existing flat namespace with a prefab namespace is rejected as a mode conflict;
perform an explicit source migration instead. The GLB transform hierarchy remains
baked into geometry in either mode.

Agents can distinguish `Transform` (local), `GlobalTransform` (world matrix), and
`Hierarchy` (current/source parent and prefab identity). `inspect` accepts a
`parent` selector for direct children. Check `parent_in_active_scene` before
treating a reported parent ID as addressable in the active scene instance.
