# Canonical pose reads

Local gameplay writes still use ordinary `Query<&mut Transform>`,
`edit_transform`, or deferred `TransformEdits`. Scene JSON, parent relationships,
interpolation policy and agent request/response schemas are unchanged.

Derived poses now live in engine-owned `GlobalTransforms` and
`PresentedTransforms` resources. `GlobalTransform` and `PresentedTransform` remain
copyable read values, but are no longer Bevy components. This intentionally breaks
Rust code that queried, inserted, removed or observed those derived components.
It removes their repeated ECS matrix writes and output-repair scans.

Replace a query of global components with an entity query and a resource read:

```rust
fn read_positions(entities: Query<Entity, With<Moving>>, globals: Res<GlobalTransforms>) {
    for entity in &entities {
        if let Some(matrix) = globals.get(entity).and_then(|pose| pose.matrix()) {
            let position = matrix.w_axis.truncate();
            // Read authoritative world position here.
        }
    }
}
```

For direct world reads, replace `world.get::<GlobalTransform>(entity)` with
`world.resource::<GlobalTransforms>().get(entity)`. Replace presented-component
reads with `world.resource::<PresentedTransforms>().get(entity)`. Use
`get_resource` when the world may not have initialized the engine's stores.
Returned values are copies; modifying one does not change engine state.

`None` from a store lookup means no admitted/prepared entry. A returned pose with
`matrix() == None` represents an invalid entry. Freshness is still defined by
boundaries: refresh authoritative transforms after an immediate out-of-band edit;
only extraction updates presented poses. Authoritative refresh and collision
queries preserve the last presentation. Default paused step/render/capture remain
exact current state, and explicit fractional previews do not advance gameplay.

`Changed<GlobalTransform>` and `Changed<PresentedTransform>` no longer apply.
Read after the named propagation/extraction boundaries. Consumers that retain
per-entity state can use a `TransformIndex::default()` hint with a store's
`get_indexed_with_revision(entity, &mut hint)` and compare returned output
revisions. The store validates the entity and hint before access; do not treat a
cached index or revision as a persistent scene identity.
Topology rebuilds or reindexing may conservatively change an output revision
even if its matrix is unchanged, as may re-evaluating a leaf whose matrix is
deferred ([decision 016](../adr-016-deferred-leaf-globals.md)).
Values also expose `revision()`. A revision of `u64::MAX` is explicitly
uncacheable after stamp exhaustion; recheck the value rather than reusing cached work.

Custom consumers of borrowed `RenderFrame` values must read slot poses with
`frame.model(slot)`. `frame.snapshot().instances[slot].model` is no longer
updated for retained frames; mesh, texture and color fields still are. Uploaders
of changed slots can instead copy `frame.pose_rows()[slot]` (`PoseRows`, the
transposed top three matrix rows), which extraction rewrites whenever that slot's
`pose_changes()` stamp advances. Owned snapshots from `Engine::extract` and
`extract_with_presentation` are unchanged (since 2026-10-03 they copy a
CPU-prepared frame; see [single sources](0.1-single-sources.md)).

The agent names `GlobalTransform` and `PresentedTransform` still select
entity-scoped projections with the same `{valid, matrix, translation}` shape.
An unprepared transformed entity reports null presented values, preserving the
existing protocol even though typed storage lookup can return `None`.
See [decision 013](../adr-013-canonical-poses-and-retained-rendering.md).
