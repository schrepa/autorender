# Collision primitives and scene version 4

Existing engine clients remain colliderless until they add `CollisionPlugin`
and `Collider` components. Existing scene versions 1–3 retain their semantics.
No collision geometry is inferred from meshes by the engine or importer.

For authored collision, change a scene to version 4 and advance its saved
revision through the normal source-save workflow. An object can contain:

```json
"collider": {
  "shape": {"kind": "cuboid", "half_extents": [0.5, 0.5, 0.5]},
  "memberships": 1,
  "filter": 4294967295,
  "sensor": false
}
```

The sphere alternative is `{"kind":"sphere","radius":0.5}`. Dimensions are
local to the object's transform. Use a child for an offset collision volume;
meshes and colliders have independent geometry. Both participants' layer filters
must admit the other's membership bits. Zero masks intentionally match nothing.

Gameplay can cast/overlap/raycast the `CollisionWorld` synchronized before
`FixedSimulation`. Sensor consumers run in `FixedPostSimulation` after
`CollisionSystems::Detect`. Refresh explicitly after out-of-band transform edits
when a query must observe those edits immediately. Inspect completeness before
using sensor transitions, and handle query errors as incomplete information.

Crystal Garden's saved scene is now version 4/revision 5. Its player and pickups
must be root transforms with authored colliders; static solids can be parented
or invisible. The example's former implicit Y=0 floor and axis-aligned obstacle
routine have been replaced by authored geometry and engine shape casts. Older
game scenes need these colliders before being loaded by the updated game.

The new fixed pre/post schedules also exist without collision. Post-simulation
commands now precede the interpolation history endpoint. Register extensions in
the named schedules rather than relying on plugin insertion order.
