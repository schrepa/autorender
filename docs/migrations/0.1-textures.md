# Texture and import migration

This records the texture milestone. The later [hierarchy migration](0.1-hierarchy.md)
introduces the current version 3 schema and importer output.

The unpublished 0.1 SDK adds `MeshVertex.uv`, `AssetBudget.max_textures`, `Texture`, `TextureHandle`, and `Material::textured`. Existing `Material::new` remains untextured. Rust struct literals must supply UVs; use `..AssetBudget::default()` for unchanged budgets. Material texture references are weak: removing a texture invalidates rendering dependencies without making existing materials own its pixels.

Low-level `RenderInstance` constructors now supply `texture: Option<TextureHandle>`. `RenderSnapshot` includes distinct `RenderTexture` sources for referenced handles. Prefer normal extraction. Batches now group by mesh and texture; per-instance color does not split draws. GPU vertices are 32 bytes instead of 24.

Scene documents now use version 2 for textures and nonzero UV data. Existing untextured version 1 JSON still loads unchanged. To add textures, set `version` to 2, advance the source revision, add `textures`, set `materials[].texture` to an authored ID, and provide UVs for inline geometry. Primitive recipes supply UVs. Regenerate the schema with `cargo xtask schema`; `docs/schema/scene-v2.schema.json` describes current input and the v1 schema remains historical.

The import command upgrades a target scene to version 2 before its guarded save. GLB node hierarchy is baked into geometry, not reconstructed as runtime parents. A changed node index changes the generated entity ID; explicit replacement preserves authored placement/tags only for matching IDs.

`BrowserStats` adds texture count, byte and upload observations. Rebuild generated Wasm bindings and the host together. The optional `Mesh3d` projection adds texture readiness and dimensions; `assets` adds bounded authored texture observations. Import/PNG dependencies remain native-only. See [import workflow](../asset-import.md) for current bounds and unsupported features.
