# Single-source statistics and structure migration

The workspace remains an unpublished 0.1 development SDK.

- Frame statistics have one definition. `engine_render::RenderStats` is the
  renderer's report and `engine::browser::FrameStats` adds the host's CPU
  observations, embedding the renderer's as `render`. Both serialize with
  serde; `BrowserApp::stats_json` returns the flat JSON object hosts and
  agents read, with the field names agents already used (`shadow_draws`,
  `local_lights`, `lod0_instances`, `render_passes` and the rest).
- The generated `BrowserStats` class is gone. Runtimes' `stats()` returns that
  JSON text: parse it once (`readStats` in `web/src/host.ts`), with nothing to
  free. TypeScript declares only the fields it reads; new statistics need no
  web changes.
- `RenderStats` lost its nested `ShadowStats` and `LightStats` and the
  `lod_instances` array: their values are the flat fields above. Read-backs
  not yet available are `null` in the JSON.
- Look settings have one definition. `RenderSnapshot`'s thirteen settings
  fields are one `environment: Environment` (`engine_core`), sanitized:
  read `snapshot.environment.shadows` for `snapshot.shadows`,
  `environment.decals` for `decal_settings` and
  `environment.reflection_probes` for `reflection_probe_settings`.
  `Environment::current(world)` reads every setting, missing effect
  resources as off.
- `engine_scene`'s `SceneShadows`, `SceneAmbientOcclusion`, `SceneBloom`,
  `SceneLocalLights`, `SceneSunShafts`, `SceneReflections`,
  `SceneRefraction`, `SceneParticles`, `SceneDecals`,
  `SceneReflectionProbes`, `SceneVirtualGeometry`, `SceneLevelOfDetail` and
  `SceneBounds` are gone. Scene environments and the `environment` control
  hold `engine_core`'s settings types (`Shadows` and so on), which
  serialize in the same JSON shape; their `resolve(path)` is `validate()`,
  returning `InvalidSetting { field, rule }`, and documents and controls
  still report `invalid_environment` at the field's path. `SceneAtmosphere`
  stays the atmosphere's authoring form, a preset with overrides, checked by
  `Atmosphere::validate`; `Atmosphere::sanitized` is the default for any
  atmosphere `validate` refuses, as before.
- Scenes and the `Shadows` and `Environment` projections write a shadow
  `cascades` count only when it is not 3, a null count reads as omitted, and documents before version 6 may hold the default
  count but no other (before, they could hold none). The generated scene
  schema and development schemas are unchanged byte for byte.
  `engine_core`'s optional `schema` feature, which `engine_scene`'s enables,
  derives the settings types' schemas.
