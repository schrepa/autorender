# Repository map

Read `README.md` for setup and `docs/architecture.md` for the frame and ownership contracts.
`engine-repository-guide.md` is the original design input, not a list of already implemented features.

- `crates/engine_core`: Bevy-based gameplay API, clocks, scene data, render extraction. No GPU or browser imports.
- `crates/engine_collision`: opt-in affine primitive collision, bounded spatial queries, sensor snapshots.
- `crates/engine_math`: branch-free, deterministic `f32` trigonometry used by the engine, games and the vendored glam.
- `crates/engine_assets`: validated immutable CPU assets, typed handles, bounded ownership.
- `crates/engine_scene`: versioned authoring, scene validation, transactional instantiation, explicit disposal.
- `crates/engine_dev`: optional inspection protocol, generated schemas, guarded native source saves.
- `crates/engine_render`: GPU resources, upload layouts, WGSL, capability and surface handling.
- `crates/engine_profile`: optional bounded CPU collector and executable-selected allocator accounting; disabled hooks have no external dependencies. See `docs/profiling.md`.
- `crates/engine`: public façade and browser composition.
- `examples/orbit-demo`: game client and its generated Wasm binding surface.
- `examples/playground`: authored game, movement/collection plugin, scene reload example.
- `examples/stress-lab`: deterministic configurable stress workloads (a tower field and a procedural city, selected by `scene`), demo phase timers, production measurement UI. See `docs/stress-lab.md`.
- `web`: thin TypeScript host, input/lifecycle handling, diagnostics display.
- `tools/xtask`: shared build and verification commands.
- `tools/assetc`: native static GLB conversion with glTF metallic-roughness materials into scenes and their files; never a runtime dependency.
- `tools/vgbuild`: native virtual geometry builder (`EVG1` cluster hierarchies) and the Stress Lab's dense meshes; never a runtime dependency.
- `vendor/meshoptimizer`: meshoptimizer 1.3 with `clusterlod`, compiled only into native tools; see `vendor/meshoptimizer/VENDORED.md`.
- `vendor/glam`: glam 0.30.9 with only its `f32` sine/cosine routed to `engine_math`; see `vendor/glam/VENDORED.md`.

Agent development is the primary workflow. Read `docs/agent-workflow.md`; use `cargo xtask agent` for browser sessions and `cargo xtask scene` for structured validation/saves. Discover registered data before assuming fields. Distinguish source changes from temporary controls and verify returned revisions. Never blindly retry an uncertain mutation.

For scene files read `docs/adr-030-scene-files.md`: version 7 scenes reference image files (`textures[].uri`) and `EMB1` mesh buffers beside them; hosts fetch and decode them at load (`SceneDocument::files`, `SceneFiles`, `instantiate_with`, `loadSceneFiles`), never in the frame loop. For materials read `docs/adr-031-gltf-materials.md`: materials are glTF 2.0 metallic-roughness materials (base color, metallic-roughness, normal, occlusion and emissive maps as `TextureRef`s with samplers and `UvTransform`s, emissive color, `AlphaMode`, double-sided), authored in scene version 8 (plain texture IDs repeat from version 8 and clamp before it; `SceneDocument::upgrade` keeps that meaning). Materials without maps keep the basic shader variant and batch across materials; materials with maps draw grouped by `MaterialBinding` (maps and parameters, not color or surface), each binding with its pipeline variant. Give objects their own colors with the `Tint` component (scene version 8 `tint`, decision 033), which stays per-object data, and change materials at runtime with `AssetLibrary::replace_material` (it re-resolves every object, so not per frame). The mesh shader is `scene.wgsl` followed by the files of `meshes/` (declarations, vertex stages, shading, forward fragments, the visibility resolve, sky, decals and impostors, concatenated in that order as `gpu_data::SHADER`); run the GPU-presentation and TAA smoke checks after changing any of them. Mesh vertices are 24 bytes with octahedral normals and mesh vertex shaders write four output slots (`docs/adr-032-compact-vertices.md`); only meshes with vertex colors or second texture coordinates (`Mesh::with_colors`/`with_uv1`, `TextureRef::tex_coord`, `EMB2` buffers, decision 034) read a second stream through `_extended` entry points; keep per-object values packed and flat, and check geometry-heavy changes on the Stress Lab city. For animation read `docs/adr-035-animation-clips-and-players.md` and `docs/adr-036-skinning.md`: `AnimationClip` assets (scene version 8 `animations`, inline or `EAN1` files) play through `AnimationPlayer` components (entity `animation`) in `FixedSimulation` under `AnimationSystems::Animate`, writing local transforms that `InterpolateTransform` presents smoothly; switch clips with `SceneInstance::clip`. `Skin` (scene `skins`, entity `skin`) deforms meshes with joints (`Mesh::with_skin`, `EMB2` flag 4) by joint palettes that extraction rebuilds each frame (`RenderSnapshot::joints`) and GPU-presented frames compose in `skin_palette`; meshes with joints never enter the kept shadow map, and GPU-presented frames cull them and select their shadow casters by palette bounds (`skin_bounds_pass`, `select_skinned`) while CPU-prepared frames keep them all. Imported animated or skinned models keep their nodes (`ID.root`, `ID.nodeN`, `ID.animN`, `ID.skinN`). The playground accepts `?taa=on`. For compressed textures read `docs/adr-037-compressed-textures.md`: scene texture files may be KTX2 (Basis Universal, glTF `KHR_texture_basisu`), which the host transcodes at load with the vendored transcoder in `web/public/basis` to the adapter's BC7, ASTC or ETC2 format (`Texture::compressed`, `SceneFiles::add_compressed_image`); the renderer uploads their levels as they are and never transcodes per frame. For textured models read `docs/asset-import.md`. Use `cargo xtask asset import` and its shared scene validation; never add image decoders to the browser frame loop. Reserve generated import IDs within their namespace. Reimport with explicit `--replace` and the saved revision. Scenes store one texture level; the renderer generates mip chains on the GPU when textures become resident and samples trilinearly. Texture/UV scenes require version 2 or later; versions 1/2 retain their original semantics. Verify per-ID CPU/GPU readiness and capture the rendered result after reload.

For parents and reusable objects read `docs/adr-006-hierarchy-and-prefabs.md`. Scene version 3 supports `parent`, `prefabs` and one-entry placements. `Transform` is local; inspect `GlobalTransform` for world matrices and `Hierarchy` for source identity. Page children with `inspect` and a `parent` selector. Use checked `set_parent`/`set_parents`; gameplay must not write derived globals. Prefabs share scene assets, cannot nest, and do not imply cascade disposal. Preserve scene ownership. `--as-prefab` imports a definition without creating a placement.

For Rust edits, start `cargo xtask agent watch`; see `docs/rust-iteration.md`. While editing, use `node web/scripts/agent.mjs development`, `sessions`, and runtime commands so compiler errors cannot prevent the client from launching. A successful Rust rebuild resets gameplay and returns a new session/build ID. Failed builds preserve the previous runtime. Read diagnostics and discover the new session before sending further mutations.

For transform mutation read `docs/adr-011-in-place-transforms.md` and `docs/adr-013-canonical-poses-and-retained-rendering.md`. Use ordinary `Query<&mut Transform>` for frequent gameplay updates or `edit_transform` for immediate world edits. Read authoritative poses from `Res<GlobalTransforms>` and last-prepared poses from `Res<PresentedTransforms>` via `get(entity)`. `GlobalTransform` and `PresentedTransform` are copyable read values, not components; `Changed<GlobalTransform>` is no longer an observation API. Read after named boundaries or compare store output revisions with validated `TransformIndex` hints. `Parent` stays immutable; use checked parent helpers. `TransformEdits` remains a deferred replacement API with ordinary insertion observers; chain dependent systems before reading queued edits. An engine-owned `Changed<Transform>` filter checks metadata before fetching payloads; unchanged boundaries still visit timestamps. Successful refreshes advance the ECS change tick without advancing gameplay clocks. `bypass_change_detection` and manual change-tick edits opt out and are unsupported for transform updates. See `docs/migrations/0.1-canonical-poses.md` for typed-reader migration; agent pose JSON names/shapes remain unchanged.

For performance work read `docs/benchmarking.md` and decision 007. Use `cargo xtask benchmark` (or the direct Node runner) with a fixed configuration and retain its JSON report. Compare identical metadata and inspect per-run variation before claiming improvement. `visible_instances` is pre-budget; `instances` is submitted count; `render_candidates` is total renderables. Visibility does not own entities or evict still-referenced GPU assets. Agent `camera`, `culling` and `benchmark` controls require pause and are temporary; step benchmarks clear input and advance gameplay. Meshes share the renderer's arena buffers (`docs/adr-046-shared-mesh-buffers.md`): draws carry their mesh's `first_index` and `base_vertex`, indirect draws name visible-ID regions as first instances where `indirect-first-instance` exists, opaque batches draw in `draw_order` (variant, material, vertex class) and shadow casters in pipeline, buffer and material order; bind through `Bindings` and keep new passes state-sorted, and count WebGPU calls per pass when changing draw loops.

For transform/presentation optimization read `docs/adr-012-transform-validation-and-presentation.md`. The common matrix path proves the existing admission predicate; keep its fallback and review numerical proofs on math-library upgrades. Certified leaves defer their world matrices (`docs/adr-016-deferred-leaf-globals.md`); reads compose the same bits, and certificate bounds need the same review. Dense presentation consumes source history hints in parent-first order. Small-angle rotations use normalized linear interpolation, with larger turns using spherical interpolation; exact-current captures and authoritative simulation poses retain their contracts. Compare fractional `present` workloads as well as `step` workloads when measuring changes.

For detailed profiling read `docs/profiling.md`. `cargo xtask profile` builds separate profiling artifacts; `--attribution` keeps hot helpers out of line for function-level sampling (compare shares, then confirm on the ordinary build). Discover `ProfileCapture`, then use agent `profile` from a paused session; it resumes ordinary frames and pauses after saving bounded trace/CPU-profile artifacts. Inspect capability gaps, completeness and profiler overhead. GPU durations correlate by frame ID, not calibrated CPU/GPU clocks; memory scopes are not total process memory. Passes time themselves with named spans (`GpuProfiler::span(name)`, writing a span's begin and end; asking again in one frame returns the same span), and builds without `profiling` compile a stand-in profiler, so never add `cfg(feature = "profiling")` to pass code or numbered effect slots.

For smooth rendering read `docs/adr-008-render-interpolation.md`. Games opt local fixed-simulation motion in with `InterpolateTransform`. Authoritative transforms remain unchanged; inspect `PresentedTransform` and `PresentationState` for the last prepared extraction. Reset interpolation on teleports. Default paused step/render/capture are exact current state; explicit `present {alpha}` or `capture {alpha}` previews a fractional pose without advancing clocks. Use matched setup ticks for present/render benchmarks.

For GPU presentation read `docs/adr-014-gpu-presentation-and-culling.md`. Ordinary interpolated browser frames blend, compose, validate and cull on the GPU; the CPU pass stays the exact reference for captures, `present` previews and inspection. After a GPU frame `PresentationState::gpu_pending()` is true and `PresentedTransforms` is stale: call `Engine::prepare_presented_transforms` (refused once inputs change) or opt out with `BrowserApp::set_gpu_presentation(false)`; never feed display poses back into simulation. Preview the GPU path with `present`/`capture` `{alpha, gpu: true}`; GPU-frame visible counts are read back a few frames late. GPU-presented frames that cull without an instance budget also cull occluded instances in two drawing phases around a depth-pyramid test (`docs/adr-040-occlusion-culling.md`, `BrowserApp::set_occlusion_culling`, Stress Lab `?occlusion=off`); output stays pixel-identical, and `rendering.occluded_instances` reports what it left undrawn. The same frames leave instances whose projected bounds cover no pixel center undrawn (`docs/adr-041-subpixel-culling.md`, `BrowserApp::set_subpixel_culling`, Stress Lab `?subpixel=off`), reported as `rendering.subpixel_instances`. Depth is reversed on a 32-bit float buffer (`docs/adr-042-reversed-depth.md`): `Camera::view_projection` maps the near plane to 1 and the far plane to 0, the buffer clears to 0 and depth tests keep the greater value, so shaders reading depth treat larger as nearer and 0 as sky; models must still not overlap exactly coplanar faces. Keep shader constants exact and tested against core, run `web/scripts/gpu-presentation-smoke.mjs` after presentation, culling or shader changes, compare `?presentation=cpu` in the same build, and report frames with and without a fixed tick separately.
For tick pipelining read `docs/adr-015-pipelined-fixed-ticks.md`. With GPU presentation `BrowserApp` runs one stage of the next fixed tick after each submitted frame and presents the previous interval until that tick is due. `Presentation` systems can observe an in-flight tick's gameplay effects and fixed time before its transforms, and its input is sampled up to two frames early; exact extraction, steps, resets and dev commands complete a started tick first. Opt out with `set_tick_pipelining(false)`, compare `?pipeline=off` in the Stress Lab, and count ticks as `fixed_tick` plus `fixed_tick_end` spans.

For temporal antialiasing read `docs/adr-017-temporal-antialiasing.md`. `BrowserApp::set_temporal_antialiasing(true)` (Stress Lab `?taa=on`) jitters and resolves ordinary GPU-presented frames only; captures, previews, steps and CPU-presented frames stay exact, so compare TAA visually with ordinary frames (`web/scripts/taa-smoke.mjs`), not captures. Its GPU cost scales with canvas pixels: measure `taa_resolve` and `opaque_meshes` at identical canvas sizes, alternating the setting in one page when possible, and run the TAA and GPU-presentation smoke checks after shader or presentation changes.

For lighting read `docs/adr-018-atmosphere-and-stylized-lighting.md` and `docs/adr-027-stylized-grading.md`. Set the `Atmosphere` resource (presets `day`, `golden_hour`, `dusk`, `night`) instead of editing shader constants; snapshots carry it sanitized with the camera eye, and every path shades alike. Its grade (`exposure`, `contrast`, `saturation`, `vibrance`, `shadow_tint`, `highlight_tint`; scene version 6 for the last four) sets the palette: thin fog and cool shadows against warm highlights read as vivid, while contrast 1, vibrance 0, saturation 1 and white tints keep authored colors. Keep per-fragment shading light (the opaque pass bounds large scenes) and compare looks at identical canvas sizes; the Stress Lab accepts `?look=`. Surfaces reflect environment maps (`docs/adr-043-environment-maps.md`): the sky drawn into a cube when it changes and blurred by the GGX lobe of each roughness level, read at the surface's roughness; screen-space reflections fall back to them. Reflection probes (`ReflectionProbe`, a world box `extent` with a `blend`; scene version 8 `reflection_probe`, environment `reflection_probes`) capture the still opaque objects and still lights around them into more cubes of that array, the nearest waiting probe first and `faces_per_frame` faces a frame, and surfaces inside their boxes reflect them box-projected; slots count as still after 16 frames with the same pose, captures never include moving, skinned or transparent objects, the GPU's texture array layers bound how many stay captured, and `rendering.reflection_probes`, `reflection_probe_faces` and `dropped_reflection_probes` report them (Stress Lab `?effects=no-probes`).

For materials, shadows and screen effects read `docs/adr-019-surface-materials-and-reflections.md`, `docs/adr-020-sun-shadows.md` and `docs/adr-021-ambient-occlusion-and-bloom.md`. Give materials a validated `Surface` (`Material::with_surface`; scene version 5 `surface`); texture alpha masks emission (`Texture::with_emission_mask`) for opaque materials and is coverage for masked and blended ones (decision 031); scene textures may carry alpha from version 8 and stay opaque before it. Configure `Shadows` (set `bounds` to the scene's region so the kept map never moves; `cascades` splits the near distance into maps a third as far each, `docs/adr-028-shadow-cascades-and-receiver-planes.md`), `AmbientOcclusion` and `Bloom` as resources; shadow lookups compare receiver planes, so do not reintroduce texel-proportional biases; an intensity of 0 or `enabled: false` removes an effect's work. Changing the sun redraws every still caster, so do not animate it per frame. Keep the GPU-presentation smoke check's still workload passing: GPU frames shadow still objects from the kept map, CPU frames from the per-frame map, and both must match. Report effect costs from `shadow_select`, `shadow_maps`, `ambient_occlusion`, `bloom` and `post_composite` samples; the Stress Lab accepts `?effects=`.

For point and spot lights, sun shafts, reflections, glass and particles read `docs/adr-023-local-lights.md` to `docs/adr-026-transparency-and-particles.md`. Put `LocalLight` on the entity whose mesh carries it (it follows the GPU-presented pose for free); keep ranges short; cluster lists hold every light reaching them, so `rendering.light_cluster_overflow` counts only entries beyond an optional `lights_per_cluster` budget or storage still growing; tune `LocalLights` (`intensity`, `distance`, optional `max_lights` and `lights_per_cluster` budgets). `SunShafts` and `Reflections` are opt-in resources (they need shadows and glossy surfaces respectively). Transparency is a material `opacity` below 1 (`Material::with_opacity`), blended order-independently without depth writes or shadows. Glass is a material `Transmission` (`Material::with_transmission`, scene version 8 `transmission`/`ior`/`thickness`, glTF `KHR_materials_transmission`); the opt-in `Refraction` resource (environment `refraction`) makes it bend and blur the opaque scene behind it (`docs/adr-038-glass-and-refraction.md`), and without it glass blends as plain transparency. Particles are stateless (`ParticleEmitter`, a function of presentation time); `Particles::max_particles` is an optional budget where the nearest emitters win. Decals (`docs/adr-039-decals.md`) project a material onto the opaque surfaces inside an entity's unit box (`Decal`, scene version 8 `decal`, `alpha` or `multiply` blends) from the depth buffer after the opaque pass; `Decals` (environment `decals`) is on by default with an optional `max_decals` budget, and `rendering.decals`/`dropped_decals` report them. Scene version 6 authors `light`, `particles`, `opacity` and the new environment sections; the Stress Lab toggles each with `?effects=no-lights,no-shafts,no-reflections,no-particles`. Run the GPU-presentation and TAA smoke checks after changing any of them.

For dense meshes read `docs/adr-044-virtual-geometry.md`: `tools/vgbuild` builds `EVG1` cluster hierarchies offline (`VirtualMesh`, validated on decode), and `Mesh::from_virtual` keeps a fallback cut that every path not drawing clusters draws. Retained frames select the clusters of opaque virtual batches on the GPU by the `VirtualGeometry` resource's `pixel_error` and draw them per material bin in the first opaque phase (`vs_virtual`); read `rendering.virtual_clusters`, `virtual_triangles`, `virtual_shadow_clusters`, `virtual_shadow_triangles`, `virtual_occluded_clusters` and `dropped_virtual`. Two-phase GPU-presented frames test the camera's clusters, not virtual instances, against depth pyramids: clusters the last frame's pyramid hid wait for this frame's and draw in phase two unless hidden, so output stays exact. They cast into the cascades and the moving map, never the kept map, with clusters chosen as the camera sees them so nothing shadows itself for want of matching detail; keep shadow views' error rule monotonic up the hierarchy. Hosts load each file's prefix (its metadata and pinned coarse pages: `virtual_mesh` scene files, `virtual_prefix_bytes`, `SceneFileSet::add_virtual_mesh` with the file's URL, served with byte ranges) and renderers stream the other 128 KiB pages by byte range as views request them, into a pool the optional `max_resident_pages` budget bounds; read `rendering.virtual_resident_pages`, `virtual_loading_pages`, `virtual_missing_pages` and `dropped_virtual_pages`, and present frames until missing and loading pages stay 0 before capturing a view at full detail. The camera's clusters shade through a visibility buffer (`docs/adr-045-visibility-buffer.md`): a pass records which triangle covers each pixel, compute lists each material bin's 8x8 tiles, and each bin's resolve rebuilds its pixels' triangles and shades them once with the forward shading functions and explicit derivatives; alpha-masked materials, `VirtualGeometry::visibility_buffer` off (environment `visibility_buffer`, Stress Lab `?visibility=off`) and devices binding fewer than 8 storage buffers per stage (11 with local lights) draw forward, and `rendering.visibility_buffer` reports which ran; keep the resolve's shading (`meshes/resolve.wgsl`) in step with forward fragments when changing `meshes/shading.wgsl`. Scenes reference them as version 8 `virtual` mesh sources (`EVG1` files beside the scene) and set the environment's `virtual_geometry` section; `cargo xtask asset import` builds them for opaque primitives of 512 triangles and up (`--virtual-triangles N`, `--no-virtual-geometry`). The Stress Lab's `scene=dense` needs `cargo run -p engine_vgbuild --release --bin dense_assets` first; run `web/scripts/virtual-geometry-smoke.mjs` after changing virtual geometry.

For levels of detail read `docs/adr-047-levels-of-detail.md`: the renderer builds each mesh's chain at upload (`mesh_lods`, meshoptimizer 1.3's simplifier ported bit-exactly as `engine_assets::simplify`; none for meshes under 64 triangles, with joints or virtual geometry) and stores the levels after the mesh's indices in the arena. GPU-presented frames that cull without an instance budget pick each instance's level in the culling pass by projecting its error from its distance to the eye against the `LevelOfDetail` resource's `pixel_error` (scene version 8 environment `level_of_detail`, Stress Lab `?lod=off`), compact levels as `vec4` buckets into their own visible-ID planes and draws, and shadow maps pick one level per group within half a texel; CPU frames, probes, transparent, skinned and virtual groups draw level 0, so GPU captures may differ from the exact CPU reference within the pixel error. Read `rendering.lod0_instances` to `lod2_instances`, and run `web/scripts/lod-smoke.mjs` after changing levels or culling. Impostors (`docs/adr-048-impostors.md`) are the coarsest level: opaque, non-skinned draw groups of 64 triangles and up (virtual geometry from its fallback cut) bake their mesh and material the first frame they draw into a layer of four RGBA8 arrays (8x8 octahedral frames of 16 texels, premultiplied coverage, vector normals), and instances whose impostor error (a texel, 2r/16) fits the pixel error draw as one card list that blends three frames and shades with the forward functions, looking the sun up a radius toward it. Toggle them with `LevelOfDetail::impostors` (environment `level_of_detail.impostors`, Stress Lab `?impostors=off`), budget them with `max_impostors`, and read `rendering.impostors`, `dropped_impostors` and `impostor_instances`; keep bake and draw attributes (`meshes/impostors.wgsl`) in step with `material_texels` when changing `meshes/shading.wgsl`.

For pipelines read `docs/adr-049-pipeline-preparation.md`: every render and compute pipeline goes through `crate::pipelines::{render, compute}`, which count creations (`rendering.pipelines`, `pipelines_created`, `pipelines_compiling`). Build pipelines only for passes a frame runs and prepare whatever the content will need (reflection-probe captures with the first frame that has probes) in the frame's setup, never while encoding; mesh variants share one `(PassKind, Variant)` map whose BASIC entries are the base pipelines. `PassKind` names a mesh pass (`MeshPass::Opaque(Targets)`, transparent or probe), whether it is lit and whether it draws affine slots. Every pipeline drawing into the frame's main color targets (meshes, sky, impostors, virtual geometry and visibility resolves) takes its formats, color target states, constants and entry-point suffix from `render_graph::Targets` (`crate::targets`), so don't add another per-target enum. Main-view material variants stay specialized by override constants; rarely drawn passes (probe captures, impostor bakes) use `Variant::uber`, which reads map presence from the material uniform's variant bits. Build fullscreen passes with `pipelines::fullscreen` and compute passes with `pipelines::compute_entry`. Declare every pipeline's layout (never `layout: None`) and let passes of a family share one built from `pipelines::Slot`s, filling bindings a pass skips with `pipelines::Fillers`: each distinct layout costs Firefox about 150 ms on integrated Intel GPUs, while layouts whose groups list the same sequence of uniform, read-only and read-write bindings share that cost. Ordinary sessions compile behind a hidden canvas: the host renders the starting state with zero elapsed time until rendered frames stop creating pipelines and the GPU has compiled them (status `preparing`), then starts play. Measure startup with `artifacts/ff-startup.mjs` and `artifacts/startup-pipelines.mjs`, and compile costs with `artifacts/pipeline-capture.mjs` plus `artifacts/pipeline-replay/`.

The renderer's frame lives in `crates/engine_render/src/browser/frame.rs` as stage methods over a `FrameState` (planning, uploads, packing, writes, each feature's preparation, pipelines, encoding, submission), and its state in per-feature parts beside it (`display`, `camera`, `instances`, `meshes`, `virtual_draws`, `visibility_draws`, `impostor_draws`, `probe_captures`). Keep every bind group built over resources of given generations in a `crate::cached::Cached` keyed by those generations, and give a new feature its own part rather than more `Renderer` fields. Large passes keep their state in parts the same way: GPU presentation's node inputs, draw groups, joints, probe faces and totals live beside `gpu_presentation/mod.rs`, shadows' maps, caster groups, regions, selection and pipelines beside `shadows/mod.rs` (what the kept map holds is `shadow_fit::KeptMap`, tested natively), and virtual geometry's arena and page streaming, selection storage, read-back feedback and layouts beside `virtual_geometry/mod.rs` (one `prepare` takes the frame's whole `SelectionFrame`), each owning its storage and a generation that advances whenever it replaces that storage, and the pass caches its bind groups by those generations instead of invalidating them by hand. Passes reading the frame's pose storage take one `FramePoses` (both pose buffers, their palettes, the slot colors, the parity and the storage generation).

Frame statistics have one definition: `engine_render::RenderStats` and the façade's `FrameStats` (which embeds it) serialize to the flat JSON object runtimes' `stats()` return and agents read as `rendering` (`docs/migrations/0.1-single-sources.md`). Add a statistic as one field with its doc comment; TypeScript declares only the fields it reads.

For the frame's passes read `docs/adr-050-render-graph.md`: every frame declares its passes in a render graph (`render_graph::plan` from the frame's `FrameShape`), each listing the resources it reads and writes and how it draws into its attachments (`Clear`, `Draw`, `Load`, `ReadOnly`). Compiling the graph checks that every pass reads what an earlier one wrote, culls passes whose results nothing reads, and derives each attachment's load and store operations; passes take their attachments from the compiled node (`color_attachments`, `depth_attachment`) instead of choosing operations themselves. Add a pass as a `Pass` declared in `plan` (a new reader of an attachment must declare the read, which keeps it stored) and encoded in `encode_pass`, and keep the `render_graph` tests over every frame shape passing. WebGPU synchronizes passes and has no memory aliasing, so the graph keeps the declared order. `rendering.render_passes` and `culled_passes` report what a frame ran.

For the look as data read `docs/adr-022-scene-environments-and-agent-controls.md`. Inspect `Environment` (or `Atmosphere`, `Shadows`, `AmbientOcclusion`, `Bloom`) before changing it; try looks with the paused `environment` control, which replaces only the sections it names and never changes source; persist one as a scene version 5 `environment`, which sets all four on instantiation (omitted sections take defaults). Effect resources are optional: removing one turns it off, and the renderer only creates an effect's GPU resources while it runs. Read `rendering.shadows_enabled`, `shadow_*`, `ambient_occlusion` and `bloom` to confirm what a frame ran.

For collision read `docs/adr-009-collision-and-spatial-queries.md`. Install `CollisionPlugin` explicitly; author v4 `collider` fields independently of meshes. Query authoritative `CollisionWorld`, refresh after out-of-band edits, and handle completeness/errors. Sensor consumers run in `FixedPostSimulation` after `CollisionSystems::Detect`. Agents discover `Collider`/`CollisionWorld` and use `raycast`, `overlap`, `shape_cast`, and non-consuming `collision_events`. Geometry queries never advance simulation or consume events.

For trigonometry, minimum, maximum and clamping read `docs/math.md`. Use `math::sin`, `math::cos`, `math::sin_cos`, `math::sin_cos4`, `math::min`, `math::max` and `math::clamp` from the prelude; glam's `f32` rotation constructors and `slerp` already use the same trigonometry, and clippy disallows `f32::sin`/`cos`/`sin_cos`/`min`/`max`/`clamp`. For bulk per-object math use `math::for_each4` with `Vec4` lanes. Keep these routines free of data-dependent branches and float selects, and reapply the two-function patch when upgrading glam.

For capacity read `docs/adr-029-budgets-and-device-limits.md`: never add a hardcoded capacity cap. Capacity is a setting with no budget by default (only GPU device limits bound content), settable from the engine API, scenes and agents; over a budget or device limit, drop the least important work and report it (`dropped_*`) instead of rejecting the frame. Validity guards (invalid data) and dev-protocol bounds stay constants.

Use `cargo xtask build`, `lint`, `test`, `assets`, and `docs`. Run `cargo xtask schema` after changing authored scene types; commit the generated schema. Browser smoke checks are documented in `web/README.md`.
Keep gameplay extensions in plugins/systems using the public façade. Use named schedules and explicit ordering.
Update contracts and examples when public behavior changes. Make performance claims only from measured browser workloads.
Do not add worker threading or additional asset formats without a concrete use case.
Do not hand-edit generated `web/pkg`, `web/dist`, `target`, or lockfiles.
