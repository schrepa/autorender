# Bevy Stress Comparison

This is an independent Bevy 0.19.1 browser application. It does not use the repository's engine crates. It reproduces the Stress Lab's deterministic seed, object placement, cube/octahedron vertices, texture pixels, mesh variants, local transforms, 32-child hierarchy groups, 60 Hz sine/rotation motion, optional per-frame interpolation, and overview camera. A Bevy custom material uses the Stress Lab's exact directional/ambient lighting, distance fog, linear material tint, sRGB texture sampling and SDR output encoding; the background uses the same linear fog color. Bevy's virtual time delta is capped at five fixed-step durations to approximate the source engine's catch-up limit. The default workload matches the **Maximum visual** preset: 90,000 static textured renderables, 32 mesh/material variants, no hierarchy, collision, or queries.

Run `./build.ps1` from PowerShell, then serve `public/` over HTTP, for example `python -m http.server 5182 --directory public`. Open `http://localhost:5182/`. The repo-local Rust toolchain and wasm-bindgen CLI are used by the script. A build of full Bevy may take several minutes. `Cargo.lock` is checked in for reproducibility; `target/` and generated `public/pkg/` are ignored.

The preset buttons select the source Stress Lab's visual and transform configurations plus the 90,000 moving-object case previously profiled. View buttons reproduce overview, close and look-away cameras. Click the canvas to focus; WASD/arrow keys fly, Q/E move down/up, and left-drag looks around. Movement speed follows the Stress Lab's camera controller. The full configuration can also be passed as `?config=<URL-encoded StressConfig JSON>`. For a comparison with Stress Lab, use the matching seed, camera, canvas size, DPR, browser and refresh rate. After startup settles, press **Record 10 s**; the page downloads frame-interval samples and summary FPS as JSON. This is browser `requestAnimationFrame` cadence, not Bevy's own CPU/GPU phase timing.

**Scope of parity:** Fragment lighting and fog math now match the source shader, but Bevy's mesh vertex stage, render extraction, culling and draw submission still differ from our renderer; identical input does not mean identical GPU work. This app does not implement colliders, sensors, spatial queries, or the Stress Lab's custom renderer. Configurations requesting collision work are rejected rather than silently producing misleading FPS. The interpolated transform path here is a small application system using Bevy `Transform`; it is not a Bevy built-in equivalent of our GPU presentation path. Compare transform and rendering workloads separately from collision workloads.
