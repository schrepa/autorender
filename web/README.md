# Browser host

Owner: browser integration. TypeScript owns the DOM, input accumulation, requestAnimationFrame, page visibility, and the diagnostics display. The Rust `Game` owns gameplay and GPU state. Input crosses the Wasm boundary once per frame as scalar values; stats are polled four times per second. No Wasm-memory view is retained by JavaScript.

Run from the repository root with `cargo xtask dev` using Node24 or later. The cube example is `/`; the authored game is `/playground.html`. `cargo xtask build` writes deployable static files to `web/dist`; serve them over HTTPS with `.wasm` as `application/wasm`. The playground fetches its local versioned scene document on startup/reload. There are no external fonts, services, or telemetry.

`npm run check --prefix web` requires bindings generated by xtask. `npm run preview --prefix web` serves the production build on port 4173. Node dependencies and lockfile are pinned. The browser owns presentation cadence; hiding or pausing the page drops pending catch-up time and clears held input. ResizeObserver sets a bounded drawing-buffer resolution. Surface/device errors stop the loop and display a useful reload message.

## WebAssembly SIMD baseline

Browser artifacts require WebGPU and standard WebAssembly 128-bit SIMD
(`simd128`). [`.cargo/config.toml`](../.cargo/config.toml) enables
`-C target-feature=+simd128` for `wasm32-unknown-unknown`, including production,
development, immutable watched generations, and profiling builds. Native tools
and native tests retain their normal target settings. Custom `RUSTFLAGS` that
override Cargo's target flags must retain this feature.

The pinned `glam` uses its Wasm SIMD implementations for supported vector,
quaternion, and matrix operations when that target feature is enabled. This
does not enable relaxed SIMD, fast math, workers, or shared memory. Browser
measurements determine the effect on a workload; enabling SIMD alone is not a
frame-rate claim.

The shared [binding loaders](src/bindings.ts) validate a tiny SIMD module before
loading any of the three games and report a clear requirement error if support
is unavailable. There is one artifact variant, with no scalar fallback. SIMD
shipped in [Chrome 91 and Firefox 89](https://v8.dev/features/simd#simd-support-in-browsers)
and [Safari 16.4](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/).
The capability probe checks the actual environment rather than a browser name.
Rebuild the Wasm artifacts after changing target flags; restart the managed
watcher after host changes as described in [Rust iteration](../docs/rust-iteration.md).

## Browser verification

Start the dev server, then run:

```sh
npm run smoke --prefix web
```

The smoke runner uses installed Chrome through Playwright. Set `BROWSER_CHANNEL=msedge` to use Edge, `DEMO_URL` to change the URL, or `SOFTWARE_GPU=1` to request SwiftShader for headless CI without a suitable GPU. Headless verification enables unsafe WebGPU for test compatibility; normal users do not need test flags on supported hardware. Software rendering checks correctness, not hardware performance. `npm test --prefix web` runs dependency-free keyboard/touch ownership and edge tests; xtask also runs them.

It checks both games, WebGPU startup, workload changes, per-mesh draws, pause/resume, keyboard/pointer input, resize, collection/jumping, scene revisions, failed reload preservation, repeated reload asset residency, error-free execution, and unsupported browsers. Desktop and narrow-viewport screenshots are written under ignored `artifacts/` for inspection. A narrow viewport is a layout check, not a physical mobile GPU test.

`host.ts` owns shared lifecycle/render scheduling; `input.ts` owns bounded independent keyboard/touch sources and action transitions. Game entry modules only initialize generated bindings and provide game-specific loading/HUD behavior. Abortable listeners and initialization signals prevent disposed hot-reload sessions from restarting stale runtimes. Normal page suspension retains the live world for resumption.

The HUD samples CPU stage timings and browser frame cadence. Run `cargo xtask benchmark`
for fixed workloads, culling A/B comparisons, metadata and versioned JSON reports;
see [benchmarking](../docs/benchmarking.md). GPU timestamp queries are not implemented.

## Agent sessions

See [agent workflow](../docs/agent-workflow.md) and [bridge protocol](scripts/agent.README.md). `dev.ts` installs the optional interface only in Vite development mode with `engine_dev=1`. It coordinates commands between frames and locks controls across source fetches/capture waits. The Rust development adapter owns inspection and simulation; JSON stays off the normal frame loop.

Development aliases bindings to `pkg-dev`, separate from production `pkg`. Scene sources and the image and buffer files beside them are excluded from Vite automatic reload and served by a bounded local middleware, so newly created files are available and saves become visible only on explicit reload. `source.ts` enforces a 64 MiB streaming fetch budget on sources and `loadSceneFiles` fetches and decodes referenced files with the browser's own decoder (decision 030); KTX2 images transcode with the vendored Basis Universal transcoder in `public/basis` to the first block-compressed format the adapter samples (`ktx2.ts`, decision 037), loaded only for scenes that reference one. Production has no development middleware, adapter import, or scene query selector.

Run `node web/scripts/agent-smoke.mjs` for the full source-save/browser loop and `node web/scripts/agent-lifecycle-smoke.mjs` for runtime replacement/navigation. Both require the development server and installed Chrome. The first uses an isolated disposable scene, and both close their own browser sessions. `cargo xtask test` includes bridge and development adapter unit contracts alongside input tests.

`cargo xtask agent watch` owns an automatic Rust iteration session. `iteration.mjs` composes the content watcher, serial build coordinator, native build worker, generation server, and shared browser owner. `bindings.ts` loads the immutable generation selected by the managed URL; production keeps its normal generated imports. Managed host HMR is disabled so a host edit cannot silently replace a Rust session. Read [Rust iteration](../docs/rust-iteration.md) for source coverage and restart rules. `iteration-smoke.mjs` verifies actual changed gameplay after a compiler error and repair.

`node web/scripts/texture-smoke.mjs` checks imported textured scenery through the development interface. It routes disposable scene responses to test readiness, GPU residency, invalid replacement preservation, visual pixel changes, upload reuse, and retirement without editing source. Set `DEMO_URL` to a development server; production intentionally has no inspection API. The host polls texture counters with existing aggregate stats and does no image decoding in frames. See [asset import](../docs/asset-import.md).

`node web/scripts/hierarchy-smoke.mjs` checks the current hierarchy/prefab sample in real Chrome. It discovers the local/world/hierarchy projections, pages direct children, steps the player and attached accessory, and compares complete world matrices under rotated nonuniform ancestors. Browser-only scene fixtures exercise independent prefab placements, shared CPU/GPU assets and draw counts, warm upload reuse, invalid cycle/parent/qualified-ID reload preservation, repeated replacement, and instance removal. A template child is rotated in the routed fixture to exercise shear; repository source stays unchanged. Screenshots are written under `artifacts/hierarchy-smoke-*/`, and the runner closes its browser. Use `DEMO_URL`, `BROWSER_PATH`/`BROWSER_CHANNEL`, and `SOFTWARE_GPU` as with the other development smoke checks. Run against fresh development Wasm bindings; production deliberately exposes no inspection interface.

`node web/scripts/culling-smoke.mjs` compares canvas pixels with visibility enabled
and disabled for camera-plane intersections, angled views, hierarchy shear and a
camera inside geometry. Routed sources also verify first-visible upload, offscreen
residency, return without reupload and actual removal/retirement. It closes its
own browser and writes captures under `artifacts/culling-smoke-*/`.

`benchmark.ts` is imported only by the development adapter. Sampling runs at RAF
boundaries, excludes warm-up from results, frees each statistics binding, and
aborts on resize, suspension, disposal or timeout. It does not run during ordinary
game frames. The host's busy boundary blocks competing commands while sampling.

`node web/scripts/interpolation-smoke.mjs` exercises opt-in presentation through
the agent interface: intermediate poses, inherited child motion, exact captures,
discontinuity resets and matching draw/culling poses. Its disposable browser
fixtures leave scene source unchanged. Explicit `capture {alpha}` captures a
fractional pose; ordinary capture remains exact. Benchmark mode `present` samples
alpha 0.5 without advancing ticks. See [interpolation](../docs/adr-008-render-interpolation.md).

`node web/scripts/gpu-presentation-smoke.mjs` loads Stress Lab with 6,000 moving
hierarchical objects, once interpolated and once without interpolation (moving
nodes then compose on the GPU from their current locals), then with none moving
after a second of frames, so GPU frames shadow them from the kept map
([decision 020](../docs/adr-020-sun-shadows.md)), and compares `capture {alpha, gpu:true}` with the exact CPU
capture of the same fractions from two camera views. It requires at most 0.1% of
pixels to differ beyond a small tolerance, visible counts within 0.1%, counters
that partition candidates, unchanged ticks, inspection materializing the pending
GPU frame and GPU-presented ordinary frames. Captures go under
`artifacts/gpu-presentation-smoke-*/`. See
[GPU presentation](../docs/adr-014-gpu-presentation-and-culling.md).

`node web/scripts/virtual-geometry-smoke.mjs` loads the Stress Lab's dense scene
(build its files first with `cargo run -p engine_vgbuild --release --bin
dense_assets`) and checks virtual geometry ([decision 044](../docs/adr-044-virtual-geometry.md)):
loading fetches under a quarter of the files' bytes (their prefixes); the
`VirtualGeometry` settings are discoverable and read as their environment
section; at a street-level and a ground-level camera, once pages stop loading
and the views lack none, GPU-presented captures (which cull occluded and
sub-pixel clusters) match CPU captures within 0.1% of pixels, both resolve
through the visibility buffer and match forward shading within 0.1% of pixels
([decision 045](../docs/adr-045-visibility-buffer.md)), clusters draw and
cast shadows and nothing is dropped; pages streamed beyond the pinned ones; a
budget of 8 pages keeps at most 8 resident, reports the rest missing and dropped,
and captures still match; CPU-prepared frames looking at bare ground retire the
other meshes and rebuild the arena, and the view looks the same afterwards; a pixel error of 6 draws fewer triangles, disabling
falls back to the fallback cuts, invalid settings are refused, and the page logs
no errors. Captures go under
`artifacts/virtual-geometry-smoke-*/`.

`node web/scripts/taa-smoke.mjs` loads Stress Lab with temporal antialiasing
(`?taa=on`) and checks that captures are identical with the setting on and off
and after temporal frames, that converged still frames are smoother (lower total
variation) with the same 8×8 block averages and do not flicker, that
CPU-presented frames stay exact, and that moving frames keep their detail.
Screenshots hide the viewport overlays and go under `artifacts/taa-smoke-*/`.
See [temporal antialiasing](../docs/adr-017-temporal-antialiasing.md).

`node web/scripts/collision-smoke.mjs` verifies geometry queries, symmetric layers,
sensors, affine hierarchy targets, swept movement, and read-only query semantics
in real Chrome. It uses disposable routed scenes and saves a screenshot/report
under `artifacts/collision-smoke-*/`. Run against development bindings.
